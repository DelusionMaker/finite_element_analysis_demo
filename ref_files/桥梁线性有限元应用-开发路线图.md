# 桥梁线性有限元结构分析应用 · 开发路线图

> 范围：**空间杆系（梁单元 + 桁架单元）线性静力分析**
> 形态：**独立新应用**，纯前端 Web（React + TypeScript），求解内核零 UI 依赖
> 目标产出：导入/搭建桥梁杆系模型 → 施加荷载与约束 → 求解位移与内力 → 三维变形与内力可视化

---

## 0. 架构总原则：内核与界面彻底解耦

```
bridge-fem/
├─ packages/
│  └─ core/                 # 求解内核，零 UI 依赖，可在 Node/浏览器/Worker 中运行
│     ├─ src/
│     │  ├─ model/          # Node / Element / Material / Section / Support / LoadCase
│     │  ├─ section/        # 截面特性：A, Iy, Iz, J 计算（矩形/工字/箱形/圆/任意多边形）
│     │  ├─ element/        # beam3d.ts（12×12 刚度）、truss3d.ts、transform.ts（方向余弦）
│     │  ├─ assemble.ts     # 自由度映射、总刚组装
│     │  ├─ solver/         # ldlt.ts、skyline.ts、renumber.ts（Cuthill–McKee）
│     │  ├─ postprocess.ts  # 杆端力回代、沿杆截面内力插值、包络
│     │  └─ index.ts
│     └─ test/              # 解析解对拍（回归测试）
└─ app/                     # React + Vite + R3F 界面
   ├─ src/viewer/           # 三维主视图（R3F）
   ├─ src/panel/            # 右侧状态栏
   ├─ src/charts/           # N / V / M 沿桥轴曲线
   └─ src/worker/           # 求解放进 Web Worker
```

**为什么这么分**：`@fem/core` 不 import 任何 React / Three.js。将来要接 Python 后端、编译成 WASM、或搬到 Node，只换调用层。同时单测可以在 Node 里直接跑，不需要浏览器环境。

### 阶段 1 · 数据模型（1.5 人日）

```ts
interface Node      { id: number; x: number; y: number; z: number }
interface Material  { id: number; E: number; nu: number; rho: number; alpha: number }  // G = E/2(1+nu)
interface Section   { id: number; A: number; Iy: number; Iz: number; J: number; refVector?: Vec3 }
interface Element   { id: number; i: number; j: number; mat: number; sec: number
                      type: 'beam' | 'truss'; releaseI?: boolean; releaseJ?: boolean }
interface Support   { node: number; ux: boolean; uy: boolean; uz: boolean
                      rx: boolean; ry: boolean; rz: boolean
                      spring?: [number, number, number, number, number, number] }  // 弹性支承
interface LoadCase  { id: number; name: string
                      nodal: { node: number; f: Vec3; m: Vec3 }[]
                      distributed: { elem: number; qLocal: Vec3 }[]
                      prescribe: { node: number; dof: number; value: number }[] }   // 支座位移 / 强制位移
```

决策点：

| 事项 | 建议 | 理由 |
|---|---|---|
| 单位制 | 全局统一 **N–mm–MPa** 或 **kN–m**，写进 README 并在 UI 顶部常显 | 桥梁常用 N/mm² 与 mm，混用是"差 10⁶ 倍"的头号来源 |
| 数据结构 | 初期用对象数组 + `Map<id, T>`；自由度与矩阵用 `Float64Array` | 可读优先；矩阵必须连续内存，否则求解慢一个量级 |
| 温度荷载 | v1 只做整体升/降温（`ε₀ = αΔT`）；梯度温度留到 v2 | 梯度温度会在截面内产生自应力，纯梁单元无法直接表达 |

交付物：`core/src/model/*` + 一个能手工构造 3 跨连续梁的 helper。
验收：能 `JSON.stringify` 出一个完整模型并反序列化回来。

### 阶段 2 · 单元刚度矩阵与坐标变换（3 人日）★ 正确性核心

#### 2.1 空间梁单元局部刚度矩阵（12×12）

自由度顺序 `[u1 v1 w1 θx1 θy1 θz1 | u2 v2 w2 θx2 θy2 θz2]`，局部 x 沿杆轴，y/z 为截面主轴：

```
         EA/L
  [  C1   0     0      0      0      0   | -C1    0     0      0      0      0   ]  u1
  [  0   12Cz   0      0      0    6Cz·L |  0  -12Cz    0      0      0    6Cz·L ]  v1
  [  0    0    12Cy    0  -6Cy·L    0    |  0     0  -12Cy     0  -6Cy·L    0    ]  w1
  [  0    0     0     GJ/L    0      0   |  0     0      0   -GJ/L    0      0   ]  θx1
  [  0    0  -6Cy·L    0    4Cy·L²   0   |  0     0   6Cy·L    0   2Cy·L²    0   ]  θy1
  [  0   6Cz·L  0      0      0   4Cz·L² |  0  -6Cz·L   0      0      0   2Cz·L² ]  θz1
  [ -C1   0     0      0      0      0   |  C1    0     0      0      0      0   ]  u2
  [  0  -12Cz   0      0      0  -6Cz·L  |  0   12Cz    0      0      0  -6Cz·L  ]  v2
  [  0    0  -12Cy     0   6Cy·L    0    |  0     0   12Cy     0   6Cy·L    0    ]  w2
  [  0    0     0   -GJ/L    0      0    |  0     0      0    GJ/L    0      0   ]  θx2
  [  0    0  -6Cy·L    0   2Cy·L²   0    |  0     0   6Cy·L    0   4Cy·L²    0   ]  θy2
  [  0   6Cz·L  0      0      0   2Cz·L² |  0  -6Cz·L   0      0      0   4Cz·L² ]  θz2

  其中 C1 = EA/L ,  Cy = EIy/L³ ,  Cz = EIz/L³
```

写入代码后**第一条单测是检查对称性** `|k - kᵀ| < 1e-12`——这一步能抓出 90% 的手抄错误。

#### 2.2 坐标变换

```
局部 x = (P_j − P_i) / L
局部 y = normalize( ref − (ref·x)·x )      ref 默认 [0,1,0]，竖杆时用 [1,0,0] 兜底
局部 z = x × y
Λ = [xᵀ; yᵀ; zᵀ]   (3×3，行向量)
T = blockDiag(Λ, Λ, Λ, Λ)   (12×12)

k_global = Tᵀ · k_local · T
u_local  = T · u_global
```

⚠️ **这是"弯矩差一倍 / 两个方向对调"的头号来源**：箱梁的 Iy 与 Iz 常常相差一个量级，局部轴一旦旋转 90°，结果完全错误。建议 UI 里提供"显示局部坐标轴"开关，并给 `refVector` 一个显式字段而不是全靠默认值。

#### 2.3 等效节点荷载

**不要手抄固端力表，直接数值积分**：

```
f_e = ∫₀ᴸ Nᵀ(x) · q  dx      N 为 Hermite 形函数（三次）
两点 Gauss 积分对三次多项式精确 ⇒ 两个积分点即可得到精确解
```

这样任意梯形分布荷载、局部任意方向的荷载都能统一处理，避免符号错误。

#### 2.4 桁架单元

可直接复用梁单元（只保留轴向项）或独立写 6×6。若要做**端部铰接释放**（`releaseI/releaseJ`），需对单元刚度做静力凝聚：把释放的转动自由度凝聚掉再组装。

交付物：`element/beam3d.ts`、`element/transform.ts`、`element/loads.ts`。
验收：算例 1、2、3、6 全部通过；`k_local` 对称性检查通过；单元在任意朝向下刚度矩阵"旋转不变"（把模型整体旋转 45°，位移大小应不变）。

### 阶段 3 · 组装、边界条件与求解（2.5 人日）

#### 3.1 自由度映射

每节点 6 个 DOF：`dof(nodeId, k) = nodeId * 6 + k`。约束 DOF 单独标记。

#### 3.2 总刚存储：先稠密，后 Skyline

| 阶段 | 方案 | 适用规模 |
|---|---|---|
| v1 | 稠密 `Float64Array(n*n)` + LDLᵀ | n ≤ 3000（约 500 节点），最直接、最好调试 |
| v2 | **Skyline（变带宽）一维存储** | n ≤ 数万。沿桥轴顺序编号时带宽 b ≈ 6×(相邻节点编号差)，通常 20–40 |

Skyline 分解代价 ≈ ½·n·b²。以 n = 6000、b = 30 计 ≈ 2.7×10⁶ flops → **毫秒级**。
配套：节点重编号（Cuthill–McKee 或直接用"沿桥轴排序"）以压小带宽。

#### 3.3 边界条件：用"置 1 置 0 + 右端修正"，不要用罚函数

```
对每个约束 DOF d，给定位移 ū：
  for 每个自由 DOF i:  F_i −= K[i][d] · ū
  K[d][*] = 0 ; K[*][d] = 0 ; K[d][d] = 1 ; F_d = ū
```

优点：**保持矩阵对称正定**，且不引入大数导致条件数恶化。弹性支承直接把弹簧刚度加到 `K[d][d]`。

#### 3.4 求解

对称正定 → **LDLᵀ 分解**（比 Cholesky 更稳，避免开方）。分解后一次前代/回代即可；多个荷载工况可复用分解结果，只重做回代（这对后续"多工况包络"至关重要）。

#### 3.5 奇异性检查

分解过程中若某主元 `|D_kk| < ε·max(diag)` → 判定为**机构（缺约束）**，返回具体 DOF 编号给 UI 提示。这一条能省掉大量"为什么位移是 1e18"的调试时间。

交付物：`assemble.ts`、`solver/ldlt.ts`、`solver/skyline.ts`（v2）。
验收：算例 4、5、7 通过；`Σ支反力 = Σ外力`（残差 < 1e-8·量级）。

### 阶段 4 · 内力回代（2 人日）

```
1. u_local = T · u_global(单元 12 个分量)
2. f_local = k_local · u_local + f_fixed_local          ← 12 个杆端力
3. 杆端内力：N（轴力）、Vy/Vz（剪力）、T（扭矩）、My/Mz（弯矩）
4. 沿杆截面内力：取 x 处左段做隔离体平衡
     内力(x) = −( i 端杆端力 + [i, x] 区间分布荷载合力 )
   每个单元采样 16–32 点，输出 N(x)/V(x)/M(x)/T(x) 数组
```

⚠️ **符号约定必须钉死**：先用一根受拉杆、一根简支梁各写一条单测把"拉为正 / 下缘受拉为正弯矩"固定下来，之后所有代码只服从这两条约定。这是后期"内力图方向相反"类 bug 的唯一解药。

交付物：`postprocess.ts`，输出 `{ nodes, elements, displacements, reactions, memberForces }`。
验收：算例 1 的 M 图应是标准三角形，最大值 = PL/4，支座处 = 0。

### 阶段 5 · 三维可视化（4 人日）★ 你的强项区

直接复用上一轮"压力与应力可视化"的方法论：

| 视图 | 做法 | 要点 |
|---|---|---|
| 几何 | R3F 线框 + 可选截面 extrude | 大模型用 `LineSegments` 合并绘制，别一个单元一个 mesh |
| 变形位形 | `x_def = x + s·u`，s 可调 | **必须在 UI 显式标注放大倍数**（桥梁挠度 mm 级、跨径 m 级，s 常取 50–200） |
| 位移云图 | 顶点色 / 自定义 shader，顺序色标（viridis） | 提供色标图例 + 单位；多工况对比时用**全局归一化** |
| 内力图 | 沿轴线生成 ribbon（宽度 ∝ \|M\|，颜色区分正负）或 3D 包络带 | 弯矩是**有符号**量 → 必须用发散色标并把 0 锚定在中性色 |
| 单元拾取 | Raycast 命中单元 → 弹出该单元 N/V/M 曲线 | 用 BVH 或按包围盒预筛 |
| 侧栏 | 模型统计（节点/单元/DOF/带宽）、求解耗时、平衡残差、工况切换、色标 | 建议沿用"3D 主视图 + 右侧状态栏"布局 |

图表侧：沿桥轴累计里程为横坐标，画 N / V / M / T 四条曲线（Recharts 或 Chart.js），支持多工况叠加与包络。

## 2. 桥梁特有的建模要点

| 主题 | 处理方式 |
|---|---|
| **建模策略** | 单梁法（快速估算）→ **梁格法 grillage**（箱梁、多片 T 梁，横向用虚拟横梁连接）→ 空间杆系（桁架拱、斜拉桥索+梁+塔） |
| **截面特性** | 写一个 `section/` 模块：矩形、工字形、箱形、圆管解析公式 + 任意多边形数值积分。**J（扭转常数）务必单独算**，薄壁箱梁的 J 与 Iy+Iz 完全不同，用错会让扭矩结果差几倍 |
| **支座** | 固定 / 单向滑动（只放某个方向约束）/ 弹性支承（板式橡胶支座：竖向抗压刚度 `K_v = E·A/t`、水平抗剪刚度 `K_h = G·A/t`）。单向支承在杆系里用"约束该方向 DOF"实现 |
| **恒载** | 一期：自重由 `ρ·A·L` 自动转为分布荷载；二期：铺装、护栏按线荷载加到主梁 |
| **活载** | v1 先做"直接布置车道荷载"；**影响线 / 移动荷载**留到 v2（见 §4） |
| **温度** | v1 只做整体升降温（自由伸缩 + 约束时产生温度力）；梯度温度留 v2 |
| **规范** | v1 只出内力与位移；荷载组合与分项系数（公路桥涵规范）作为后处理层单独加 |

## 4. 后续扩展路线（按性价比排序）

1. **多工况 + 包络**：分解一次、多工况回代；输出最大/最小包络图。成本极低、收益极高。
2. **模态分析**（子空间迭代或 Lanczos）：一致质量矩阵 `M = ∫ρ·NᵀN dV`（可用集中质量矩阵简化）；自振频率 + 振型动画，是三维展示的高光场景，而且桥梁抗风抗震必看。
3. **影响线 / 移动荷载**：桥梁最"值钱"的特色功能。做法是先对某个截面响应量做静力影响线（`Müller-Breslau` 或按单位荷载逐点求解），再用车队荷载布载求最不利效应。有了多工况求解能力后实现成本不高。
4. **施工阶段分析（顶推）**：单元激活/钝化、阶段内力累加、临时墩与顶推力、支座转换。**这正好能对接你已在推进的桥梁顶推施工三维智慧平台** —— 分阶段应力/位移历程是该平台最缺的一块"物理内核"。
5. **线性屈曲**：引入几何刚度矩阵 `K_g`，解 `det(K + λK_g) = 0`。
6. **后端化**：模型规模突破浏览器舒适区，或要做非线性/动力时程时，把 `@fem/core` 套一层 FastAPI 或 Node 服务即可，前端零改动。

## 5. 最容易踩的 8 个坑

| # | 坑 | 预防 |
|---|---|---|
| 1 | 单位制混用（N/mm² vs kN/m） | README 固定一套，UI 顶部常显，所有输入带单位后缀 |
| 2 | 局部坐标轴取向错误 → Iy/Iz 对调 | 显式 `refVector` 字段 + "显示局部轴"调试开关 + 整体旋转不变性单测 |
| 3 | 手抄固端力表符号错 | 统一改用 Gauss 数值积分求等效节点荷载 |
| 4 | 罚函数法施加约束 → 条件数恶化 | 用置 1 置 0 + 右端修正，保持对称性 |
| 5 | 缺约束导致矩阵奇异，位移 1e18 | 分解时检测小主元，直接报出可疑 DOF 编号 |
| 6 | 内力符号约定混乱 | 阶段 4 先用两根杆把约定钉死并写成单测 |
| 7 | 扭转常数 J 用错（写成 Iy+Iz 或极惯性矩） | 薄壁箱梁单独用 Bredt 公式算 J，写进 `section/` 并单测 |
| 8 | 变形放大系数未标注 → 读者误判 | UI 侧栏常显"变形 ×N"，并允许一键切回真实位形 |
